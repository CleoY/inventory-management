Request Data Flow

1
User changes a filter
FilterBar.vue updates module-level refs in useFilters.js — shared as a singleton across all views.
2
View reacts and calls the API
Each view watches the filter refs and calls getCurrentFilters() to build a params object, then calls api.js.
3
Axios sends query params
api.js builds a URLSearchParams string (skipping 'all' values) and fires a GET request to localhost:8001/api/....
4
FastAPI filters in memory
apply_filters() runs list comprehensions on the in-memory Python lists for warehouse, category, and status. filter_by_month() handles direct months (e.g. 2025-09) and quarters (Q3-2025).
5
Pydantic validates and serializes
The response_model on each endpoint validates the filtered dicts against the Pydantic model before serialization.
6
Vue updates computed properties
Raw response is stored in a ref (e.g. allOrders). Derived values — totals, charts, filtered lists — update automatically via computed().

Key Patterns

Frontend

Filter Singleton

useFilters.js declares its refs at module scope (outside the function), making them shared across every component that imports the composable. Any view reflecting filter changes does not need to pass props — it just calls useFilters().

Frontend

Raw ref + Computed

Views store the full API response in a ref (e.g. allOrders). Everything derived — totals, filtered rows, chart data — lives in computed() properties so Vue caches and invalidates them automatically.

Frontend

i18n + Currency

Locale is persisted in localStorage via useI18n.js. Switching to Japanese also switches currency from USD to JPY. Always use currency.js for formatting — not raw toLocaleString — so locale is respected.

Backend

Filter Helpers

apply_filters() handles warehouse, category, and status. filter_by_month() handles both direct month strings (2025-09) and quarters (Q3-2025). Both skip the filter when the value is 'all' or absent.

Backend

In-memory Mutation

Purchase orders and tasks are the only mutable state — modified at runtime via POST/PATCH/DELETE. All other data is read-only. A server restart reloads everything from JSON files, wiping runtime changes.

Data

JSON as Source of Truth

All seed data lives in server/data/*.json. Adding a field to JSON requires a matching update to the Pydantic model in main.py. Category names and warehouse names must be consistent across all files — filtering is case-insensitive on category, exact-match on warehouse.
